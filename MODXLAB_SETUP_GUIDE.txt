ModX Lab (Subway Surfers Mod Menu) — সম্পূর্ণ সেটআপ ও রক্ষণাবেক্ষণ গাইড

এই ফাইলে প্রথম থেকে শেষ পর্যন্ত আপনার নিজেকে যেসব কাজ করতে হবে (Firebase,
Appwrite, Ed25519 Keys, GitHub Secrets, Termux, SPKI Pin এবং MT Manager দিয়ে

সতর্কতা: এই ফাইলে কোনো আসল Password, Private Key, Service Account JSON বা
Keystore Password লিখবেন না। সেগুলো ফোনের নিরাপদ স্থানে আলাদা রাখুন।

২. Firebase Realtime Database (RTDB) সেটআপ ও ইউজার তৈরি
--------------------------------------------------------------------------------
২.১) Database Rules সেট করা:
  - Firebase Console -> আপনার প্রজেক্ট -> Realtime Database -> Rules ট্যাব।
  - প্রজেক্টের `database.rules.json` অনুযায়ী নিচের Rules বসানো থাকবে:
      * User নোট: .read = false, .write = false, .indexOn = ["user"]
      * update নোট: .read = true, .write = false
  - Publish বাটনে ক্লিক করুন।

২.২) Firebase Service Account JSON নেওয়া (শুধু Appwrite সার্ভারের জন্য):
  - Firebase Console -> Project Settings (গিয়ার আইকন) -> Service accounts।
  - "Generate new private key" ক্লিক করে JSON ফাইলটি ডাউনলোড করুন।
  - এই JSON ফাইলটি কখনোই GitHub-এ বা APK-তে রাখবেন না।

২.৩) ইউজার ও পাসওয়ার্ড তৈরি করা (Termux বা PC-তে Node.js দিয়ে):
  উপায় ক — শুধু পাসওয়ার্ডের scrypt হ্যাশ বানানো (Firebase Console-এ পেস্ট করতে):
    node scripts/migrate-passwords.js --hash "MyPass123"

  উপায় খ — কমান্ড দিয়ে সরাসরি Firebase RTDB-তে ইউজার তৈরি করা:
    FIREBASE_DB_URL="https://modx-lab-a5e41-default-rtdb.firebaseio.com" \
    FIREBASE_SERVICE_ACCOUNT_FILE="./service-account.json" \
    node scripts/migrate-passwords.js --add-user modxlab MyPass123 30

  Firebase RTDB-তে `/User/<node>`-এর ফিল্ডগুলোর নিয়ম:
    - user        : ছোট হাতের অক্ষরে ইউজারনেম (যেমন "modxlab")
    - passHash    : --hash থেকে পাওয়া "scrypt$16384$8$1$..." স্ট্রিং
                    (পুরনো plaintext "pass" ফিল্ড রাখবেন না)
    - status      : "true" (অ্যাকাউন্ট বন্ধ করতে চাইলে "false")
    - device_id   : "" (ফাঁকা রাখলে সবাই একই username/password দিয়ে যেকোনো
                    ডিভাইস থেকে লগইন করতে পারবে; এক ডিভাইসে লক চাইলে ডিভাইস আইডি দিন)
    - expire_date : "2027-12-31 23:59 +06:00" (অথবা rgtime + duration_days)

২.৪) অ্যাপ আপডেট নোটিশ (ইচ্ছামতো) — Firebase RTDB `/update/up`:
    - version : "1.0" (app/build.gradle-এর versionName-এর সাথে মিলবে)
    - message : "New update available"
    - url     : ডাউনলোড লিংক

৭. Termux থেকে লাইভ SSL SPKI Pin বের করা ও `PinnedHttp.java`-তে বসানো
--------------------------------------------------------------------------------
৭.১) Termux-এ দরকারি টুল ইনস্টল করুন:
    pkg update && pkg install git openssl-tool nodejs -y

৭.২) Firebase RTDB-এর SPKI পিন বের করুন:
    openssl s_client -servername modx-lab-a5e41-default-rtdb.firebaseio.com -connect modx-lab-a5e41-default-rtdb.firebaseio.com:443 -showcerts </dev/null 2>/dev/null | awk '/BEGIN CERTIFICATE/,/END CERTIFICATE/{ if(/BEGIN CERTIFICATE/){a++}; out="fb"a".pem"; print >out }'
    for f in fb*.pem; do echo "$f:"; openssl x509 -in "$f" -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64; done

৭.৩) Appwrite Cloud-এর SPKI পিন বের করুন:
    openssl s_client -servername sgp.cloud.appwrite.io -connect sgp.cloud.appwrite.io:443 -showcerts </dev/null 2>/dev/null | awk '/BEGIN CERTIFICATE/,/END CERTIFICATE/{ if(/BEGIN CERTIFICATE/){a++}; out="aw"a".pem"; print >out }'
    for f in aw*.pem; do echo "$f:"; openssl x509 -in "$f" -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64; done

৭.৪) `app/src/main/java/com/android/support/PinnedHttp.java` এডিট করুন:
  - `FIREBASE_PINS` অ্যারেতে fb2.pem (Intermediate CA) এবং ব্যাকআপ হিসেবে
    fb1.pem বা fb3.pem-এর Base64 স্ট্রিং বসান।
  - `APPWRITE_PINS` অ্যারেতে aw2.pem (Intermediate CA) এবং ব্যাকআপ হিসেবে
    aw1.pem বা aw3.pem-এর Base64 স্ট্রিং বসান।
  - ENFORCE_PINS = true অপরিবর্তিত রাখুন।

৯. GitHub Actions থেকে Signed Release APK ও Diagnostic APK বিল্ড
--------------------------------------------------------------------------------
৯.১) সাধারণ Release বিল্ড:
  ১. main ব্রাঞ্চে Push করার সাথে সাথে GitHub Actions -> "Build Signed Release APK"

  ২. বিল্ডটি ২ ধাপে কাজ করে:
     - Pass 1: CERT_SHA256 ও ED25519_PUBLIC_KEY বসিয়ে একক `classes.dex` বানায়
               এবং সেই একক `classes.dex`-এর আসল SHA-256 হিসাব করে।
     - Pass 2: `gradle clean assembleRelease` দিয়ে আসল DEX_HASH সহ নতুন করে

  ৩. CI শেষে Job Summary-তে Built ABIs, একক `classes.dex` SHA-256 ও Cert SHA-256 দেখাবে।
  ৪. Artifacts থেকে `ModXLab-release-signed` ডাউনলোড করুন। (এতে কোনো `"MXL"` ডায়াগনস্টিক
     স্ট্রিং থাকে না — এটিই পাবলিক বা সাধারণ ব্যবহারের বিল্ড।)

৯.২) সমস্যা ধরার জন্য Diagnostic বিল্ড (`diag = true`):
  - কখনো মেনু না এলে কোথায় আটকাচ্ছে তা দেখতে:
    GitHub Repo -> Actions -> "Build Signed Release APK" -> Run workflow
    -> `diag` চেকবক্স `[x] true` করে Run দিন।
  - Artifact নাম হবে: `ModXLab-DIAG-do-not-distribute` (এটি কখনোই পাবলিক শেয়ার করবেন না)।
  - Termux-এ ADB কানেক্ট করে লাইভ লগ দেখুন:
      pkg install android-tools -y
      adb pair <IP>:<PAIR_PORT>

--------------------------------------------------------------------------------
১০. Subway Surfers (Host APK)-এ Inject ও Sign করার সঠিক ধাপ
--------------------------------------------------------------------------------
১০.১) মোড APK থেকে ফাইল বের করা (সবসময় একই বিল্ড জিপ থেকে নেবেন):
  - `ModXLab-release-signed` থেকে পাওয়া `app-release.apk` আনজিপ / MT Manager দিয়ে খুলুন।
  - কোনো `res/` বা `assets/` ফাইল নেওয়ার দরকার নেই — কোড সম্পূর্ণ resource-independent।
  - শুধু এই ২টি অংশ নিন:
    1) একক `classes.dex`
    2) Host গেমে যেসব ABI ফোল্ডার আছে তার সাথে মিলিয়ে `lib/arm64-v8a/libModXLab.so`
       এবং/অথবা `lib/armeabi-v7a/libModXLab.so`।

১০.২) গেম (Host APK)-এ যোগ করার নিয়ম:
  - **DEX নাম্বারিং (খুব গুরুত্বপূর্ণ):** গেমের ভেতর শেষ dex কোনটি দেখুন। যদি
    `classes.dex`..`classes9.dex` থাকে, তাহলে মোডের dex-কে অবশ্যই পরের ক্রমিক নাম
    `classes10.dex` দিন। মাঝখানে কোনো সংখ্যা বাদ পড়লে (যেমন `classes10.dex` নেই,
    সরাসরি `classes11.dex`) Android ART ওই dex লোড করবে না!
  - মোডের `classes*.dex`-এর ভেতরে কোনো Smali এডিট করবেন না (তাহলে DEX SHA-256 বদলে
    গিয়ে native check fail করবে)।
  - গেমের নিজস্ব `classes.dex`-এ Main Launcher Activity-র `onCreate`-এ কল যোগ করুন:
      invoke-static {p0}, Lcom/android/support/Main;->Start(Landroid/content/Context;)V
  - **Manifest (সর্বোত্তম সেটআপ):**
      * <uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
      * <uses-permission android:name="android.permission.INTERNET" />
      * <service android:name="com.android.support.Launcher"
                 android:enabled="true"
                 android:exported="false"
                 android:stopWithTask="true" />
    (নোট: Host Manifest-এ `Launcher` না থাকলেও এখন fallback-এ মেনু চলবে, তবে
     `SYSTEM_ALERT_WINDOW` ও `Launcher` রাখলে ভাসমান ওভারলে সবচেয়ে ভালো কাজ করে।)
  - যদি গেমের Manifest-এ `android:extractNativeLibs="false"` থাকে:
      * `.so` ফাইলটি ZIP-এ `STORE` (compression level 0, uncompressed) অবস্থায় রাখতে হবে
      * এবং সাইন করার আগে `zipalign -p -f 4 input.apk aligned.apk` চালাতে হবে।

১০.৩) নিজের Keystore দিয়ে Sign করা (V1 + V2 + V3 আবশ্যক):
  - `release.keystore` দিয়ে গেম APK অবশ্যই **V2 + V3** (সাথে V1) enabled করে
    সাইন করতে হবে। শুধু V1 দিলে native v2/v3 verifier fail করবে।
  - Termux কমান্ড উদাহরণ:
      zipalign -p -f 4 host_modded.apk host_aligned.apk
      apksigner sign \
        --ks "/storage/emulated/0/keystore/release.keystore" \
        --ks-type PKCS12 \
        --ks-key-alias modxlab \
        --v1-signing-enabled true \
        --v2-signing-enabled true \
        --v3-signing-enabled true \
        --out host_signed.apk \
        host_aligned.apk
      apksigner verify -v --print-certs host_signed.apk
  - `apksigner verify`-তে অবশ্যই `v2: true` এবং `v3: true` দেখাতে হবে এবং SHA-256
    digest আপনার CI Summary-র `Signing Cert SHA-256`-এর সাথে হুবহু মিলতে হবে।
  - নোট: হোস্ট গেমের `minSdkVersion >= 24` হলে সাধারণ `apksigner verify`-তে V1
    `false` দেখাতে পারে; V1 যাচাই করতে `--min-sdk-version 21` যোগ করে দেখুন:
      apksigner verify --min-sdk-version 21 --verbose --print-certs host_signed.apk

১০.৪) Termux অটোমেটেড স্ক্রিপ্ট (`scripts/inject-and-sign.sh`) — প্রস্তাবিত পদ্ধতি:
  ১. Termux-এ প্রথমবার প্রয়োজনীয় সব প্যাকেজ ইনস্টল ও রিপো আপডেট:
      termux-setup-storage
      pkg update && pkg upgrade -y
      pkg install -y git apksigner zip unzip openjdk-21 aapt python android-tools apktool

     Termux home বা স্টোরেজে রিপো ক্লোন / আপডেট:
      cd ~
      git clone https://github.com/modxlab2/Subway-Surf-ModX-Lab.git
      cd Subway-Surf-ModX-Lab
      (আগে থেকে থাকলে শুধু: git pull origin main)

  ২. গেমে প্রথমবার Smali + Manifest এডিট (Sign ছাড়াই `base_patched.apk` তৈরি):
     - MT Manager (Auto Sign অবশ্যই OFF) অথবা `apktool` ব্যবহার করুন:
         mkdir -p ~/mod_work
         apktool d -r "/storage/emulated/0/keystore/Subway Surf_3.71.11.apk" -o ~/mod_work/host_dec
     - `AndroidManifest.xml`-এ `SYSTEM_ALERT_WINDOW`, `INTERNET` এবং `<service android:name="com.android.support.Launcher" ... />` দিন।
     - Host Main Activity (যেমন `ChiliMultidexSupportActivity`)-র `onCreate` মেথডে
       `invoke-super` লাইনের ঠিক পরে বসান:
         invoke-static {p0}, Lcom/android/support/Main;->Start(Landroid/content/Context;)V
     - `apktool`-এ রিবিল্ড করুন (Sign ছাড়াই):
         apktool b ~/mod_work/host_dec -o "/storage/emulated/0/keystore/Subway_Surf_3.71.11_base_patched.apk"

  ৩. ফোনের `release.keystore` ও GitHub `app-release.apk` একই কি না যাচাই করা
     (একাধিকবার Generate Release Keystore চালালে এটি অবশ্যই মিলিয়ে নিন):
      keytool -list -v -keystore "/storage/emulated/0/keystore/release.keystore" -storetype PKCS12 -alias modxlab | grep "SHA256:"
      apksigner verify --print-certs "/storage/emulated/0/keystore/app-release.apk" | grep "SHA-256 digest:"
     - দুটোর ৬৪-অক্ষরের কোড (`:` ছাড়া) হুবহু এক হতে হবে। না মিললে GitHub Actions ->
       "Generate Release Keystore"-এর সর্বশেষ সফল (সবুজ) রান থেকে `release-keystore-backup`
       নামিয়ে তারপর আবার "Build Signed Release APK" চালিয়ে নতুন `app-release.apk` নিন।

  ৪. অটোমেটিক Inject + Align + V1/V2/V3 Sign + Post-flight Verify চালানো:
      bash scripts/inject-and-sign.sh \
        --mod-apk "/storage/emulated/0/keystore/app-release.apk" \
        --host-apk "/storage/emulated/0/keystore/Subway_Surf_3.71.11_base_patched.apk" \
        --keystore "/storage/emulated/0/keystore/release.keystore" \
        --ks-type PKCS12 \
        --alias modxlab \
        --cert-sha256 "এখানে_৬৪_অক্ষরের_CERT_SHA256_দিন" \
        --out "/storage/emulated/0/keystore/Subway_Surf_3.71.11_signed.apk" \
        --report-bn
     - পাসওয়ার্ড `read -s` দিয়ে গোপনে নেওয়া হবে (কখনো প্রিন্ট বা সেভ হয় না)।
     - ফোনে `zipalign` না থাকলে স্ক্রিপ্ট নিজস্ব Python 4KB page-alignment fallback ব্যবহার করবে।
     - Termux টার্মিনালের monospace রেন্ডারার (এবং ডিফল্ট ফন্ট) বাংলা যুক্তবর্ণ সঠিকভাবে জোড়া (shape) দিতে পারে না বলে বাংলা লেখা ভেঙে যায়। তাই টার্মিনালের সব আউটপুট এখন সহজ ইংরেজিতে (`[OK]`, `[FAIL]`, `[STEP 1/6]`) দেখায়।
     - `--report-bn` ফ্ল্যাগ যোগ করলে একই ফোল্ডারে `inject-report-bn.html` নামে সম্পূর্ণ বাংলা HTML রিপোর্ট তৈরি হয়ে ফোনের ব্রাউজারে (`termux-open`) খুলবে (ফোনের ব্রাউজার বাংলা যুক্তবর্ণ সঠিকভাবে রেন্ডার করে)। চাইলে `pkg install termux-api` থাকলে শেষে ছোট একটি Toast নোটিফিকেশনও দেখাবে।
     - টিপস: Termux:Styling অ্যাপ দিয়ে ফন্ট বদলালেও টার্মিনালে বাংলা যুক্তবর্ণ অনেক সময় ভেঙে যায় — তাই নির্ভুল বাংলা রিপোর্ট পড়ার সবচেয়ে নির্ভরযোগ্য উপায় হলো `--report-bn` দিয়ে তৈরি HTML রিপোর্টটি ব্রাউজারে দেখা।
     - শেষে সবগুলো `[PASS]` / `[OK]` এলে তবেই তৈরি হওয়া APK ইনস্টল করুন।

  ৫. Split APKs / XAPK হলে সবগুলো Split একই Keystore দিয়ে সাইন ও ইনস্টল:
      for f in base.apk config.*.apk; do
        apksigner sign --ks "/storage/emulated/0/keystore/release.keystore" --ks-type PKCS12 --ks-key-alias modxlab --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true --out "signed_${f}" "${f}"
      done
      adb install-multiple signed_base.apk signed_config.*.apk
     - অথবা ফোনে SAI (Split APKs Installer) দিয়ে ইনস্টল করুন।
     - সতর্কতা: ফোনে আগে Play Store বা অন্য সিগনেচারের গেম থাকলে আগে Uninstall করতে হবে
       (এতে লোকাল অফলাইন গেম সেভ ডেটা মুছে যেতে পারে)।

  ৬. ইনস্টলের পর ফোনের Settings -> Apps -> Subway Surf -> Display over other apps = Allow করুন।

১১. ভবিষ্যতে কোনো কিছু পরিবর্তন করতে হলে কোথায় কী করবেন (Cheat Sheet)
--------------------------------------------------------------------------------
১. পাসওয়ার্ড বদলানো / নতুন ইউজার / মেয়াদ বাড়ানো বা ব্লক করা:
   -> শুধু Firebase RTDB `/User` আপডেট করুন (বা `scripts/migrate-passwords.js` চালান)।
   -> অ্যাপ নতুন করে বিল্ড করার দরকার নেই।

২. "New Update Available" পপআপ বা ভার্সন বদলানো:
   -> Firebase RTDB `/update/up` ও `app/build.gradle`-এর `versionName` মিলিয়ে নিন।

৩. Mod Menu-র নতুন ফিচার, অফসেট বা UI ডিজাইন পরিবর্তন:
   -> `app/src/main/jni/Main.cpp` / `Menu.java` / `LoginHelper.java` এডিট করে
      GitHub-এ push করুন -> একই নতুন বিল্ডের `classes.dex` + `libModXLab.so` গেমে দিন।

৪. Firebase বা Appwrite ডোমেইন/প্রজেক্ট আইডি বদলাতে হলে:
   -> `app/src/main/jni/Security.cpp`-এর নিচের দিকের
      getUpdateUrl / getAppwriteEndpoint / getAppwriteProjectId / getVerifyLoginFunctionId
      ফাংশনগুলো আপডেট করুন।
   -> নতুন ডোমেইনের SPKI Pin Termux দিয়ে বের করে `PinnedHttp.java`-তে বসান।

৫. হঠাৎ লগইন করার সময় "Connection failed" বা "SSL handshake error" দেখালে:
   -> ফোনের তারিখ/সময় ঠিক আছে কি না এবং VPN/AdGuard/HTTP Proxy বন্ধ আছে কি না দেখুন।
   -> সার্ভারের SSL সার্টিফিকেট পরিবর্তন হয়েছে কি না ধাপ ৭-এর `openssl` কমান্ড দিয়ে
      চেক করে নতুন পিন `PinnedHttp.java`-তে বসান।
   -> উল্লেখ্য: `PinnedHttp.java` এখন হোস্ট গেমের `network_security_config.xml`
      এড়াতে সরাসরি সিস্টেমের `AndroidCAStore` (`system:*` রুট CA) ব্যবহার করে।
   -> তবুও সমস্যা থাকলে `diag=true` বিল্ড নিয়ে `adb logcat -s MXL` দেখুন (`[301]`
      লাইন আসল TLS exception দেখাবে)।

১২. Troubleshooting টেবিল (গেমে মেনু না আসলে বা ফেল করলে করণীয়)
--------------------------------------------------------------------------------
১) ভুল Keystore বা Certificate মিলছে না (Stage 107 / 108):
   - লক্ষণ: `MXL [108]` APK cert mismatch অথবা `[107]` PackageManager cert mismatch।
   - কারণ: গেমটি Default/Test key বা অন্য keystore দিয়ে সাইন করা হয়েছে, যা CI-এর
           `KEYSTORE_BASE64`-এর সাথে মেলে না।
   - সমাধান: CI-এ যে `release.keystore` ব্যবহৃত হয়েছে ঠিক সেটি (`modxlab` alias)
             দিয়ে গেম সাইন করুন এবং `apksigner verify --print-certs` দিয়ে SHA-256 মেলান।

২) শুধু V1 Signing করা হয়েছে / V2+V3 নেই (Stage 106):
   - লক্ষণ: `MXL [106]` APK v2/v3 signature block missing।
   - কারণ: পুরনো zip-signer বা শুধু V1 scheme দিয়ে সাইন করলে v2/v3 ব্লক থাকে না।
   - সমাধান: `apksigner sign --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true`
             ব্যবহার করুন এবং Sign করার আগে `zipalign` করুন (পরে নয়!)।

৩) `.dex` এবং `.so` ভিন্ন ভিন্ন বিল্ড থেকে নেওয়া (Stage 111):
   - লক্ষণ: `MXL [111]` No .dex entry matched expected DEX hash।
   - কারণ: `classes.dex` এক বিল্ডের আর `libModXLab.so` আগের/অন্য বিল্ডের, অথবা মোডের
           `classesN.dex`-এ smali এডিট করা হয়েছে।
   - সমাধান: সবসময় একই CI Artifact থেকে `classes.dex` ও `libModXLab.so` নিন এবং মোডের
             `classesN.dex` কখনোই এডিট করবেন না।

৪) ABI অমিল — 32-bit বনাম 64-bit (Stage 201 / UnsatisfiedLinkError):
   - লক্ষণ: `MXL [201]` `System.loadLibrary(ModXLab) failed: UnsatisfiedLinkError`।
   - কারণ: গেম APK শুধু `armeabi-v7a` বা শুধু `arm64-v8a` নেটিভ লাইব্রেরি রাখে, কিন্তু
           আপনি ভুল ABI-এর `.so` দিয়েছেন (যেমন `lib/armeabi-v7a` থাকলে Android শুধু
           32-bit মোডে লোড করতে চায় অথবা `arm64-v8a` মিসিং)।
   - সমাধান: গেমের `lib/` ফোল্ডারে যেসব ABI আছে (`arm64-v8a`, `armeabi-v7a`) সবগুলোর
             জন্য সংশ্লিষ্ট `libModXLab.so` কপি করুন।

৫) DEX নাম্বারিংয়ে ফাঁক থাকা (Gap in `classesN.dex`):
   - লক্ষণ: `Main.Start` কলই হয় না বা `ClassNotFoundException: com.android.support.Main`।
   - কারণ: গেমে যদি `classes.dex`..`classes9.dex` থাকে আর আপনি `classes10.dex` না দিয়ে
           সরাসরি `classes11.dex` যোগ করেন, Android `classes10.dex` না পেয়ে থেমে যায়।
   - সমাধান: সবসময় শেষ `classes<k>.dex`-এর ঠিক পরের সংখ্যা `classes<k+1>.dex` ব্যবহার করুন।

৬) `extractNativeLibs="false"` হলে `.so` লোড না হওয়া (Stage 201):
   - লক্ষণ: Modern APK/Android 11+ এ ইনস্টল ফেল (`INSTALL_FAILED_INVALID_APK`) বা
           `dlopen failed: couldn't map libModXLab.so`।
   - কারণ: `extractNativeLibs="false"` থাকলে `.so` ফাইল ZIP-এ compress করা থাকলে বা
           4KB page-aligned না হলে Android সরাসরি mmap করতে পারে না।
   - সমাধান: `lib/*/libModXLab.so` অবশ্যই Stored (0% compression / uncompressed) হিসেবে
             APK-তে রাখুন এবং সাইন করার আগে `zipalign -p -f 4` চালান।

৭) Split APKs / XAPK / APKS প্যাকেজ সমস্যা:
   - লক্ষণ: ইনস্টল ফেল (`INSTALL_FAILED_UPDATE_INCOMPATIBLE` / signature mismatch) বা
           `base.apk`-তে সাইন করলেও split লোড না হওয়া।
   - কারণ: গেম Split APK হলে `base.apk`, `split_config.arm64_v8a.apk`, `split_config.*.apk`
           — সবগুলো ফাইল একই keystore দিয়ে সাইন না করলে Android ইনস্টল বা লোড করতে দেয় না।
   - সমাধান: সব split APK একই `release.keystore` দিয়ে সাইন করুন, অথবা সাইন করার আগে
             নির্ভরযোগ্য টুলে single universal APK-তে মার্জ করে তারপর `zipalign + apksigner` দিন।

৮) Overlay Permission না থাকা (`SYSTEM_ALERT_WINDOW`) (Stage 202 / 203):
   - লক্ষণ: `MXL [202]` Overlay permission missing অথবা ভাসমান আইকন Settings খোলার পরও
           ডায়ালগ আসে না।
   - কারণ: ফোনের Settings -> Display over other apps বন্ধ, অথবা Host Manifest-এ
           `SYSTEM_ALERT_WINDOW` নেই।
   - সমাধান: Host `AndroidManifest.xml`-এ `SYSTEM_ALERT_WINDOW` রাখুন এবং গেমের App Info
             থেকে "Display over other apps" Allow করুন। সাময়িক fallback হিসেবে `Activity`
             কনটেক্সট দিলে ইন-অ্যাপ উইন্ডোতেও মেনু খুলবে।

৯) Root / LSPosed / Xposed / Frida ডিটেকশন (Stage 101 / 102 / 103):
   - লক্ষণ: `MXL [101]` Frida, `[102]` Xposed/LSPosed, বা `[103]` TracerPid > 0।
   - কারণ: ফোনে LSPosed/Xposed মডিউল বা Frida server চালু আছে বা ডিবাগার সংযুক্ত।
   - সমাধান: গেমটিকে Magisk DenyList / Shamiko দিয়ে হাইড করুন, Xposed/LSPosed এই গেমে
             অ্যাপ্লাই বন্ধ করুন এবং Frida server বা ডিবাগার বন্ধ করে গেম চালান।

১০) গেমের ভেতর "SSL handshake error" / "SSL pin mismatch" (Stage 301):
   - লক্ষণ: Standalone `app-release.apk`-তে লগইন হয়, কিন্তু গেমের ভেতর লগইন করলে
           `SSL handshake error` দেখায় (বা `diag=true` লগে `MXL [301]` আসে)।
   - কারণ: হোস্ট গেমের `AndroidManifest.xml`-এ থাকা `network_security_config`,
           ফোনের ভুল তারিখ/সময়, VPN/Proxy, বা সার্ভারের SPKI Pin পরিবর্তন।
   - সমাধান: `PinnedHttp.java`-র আপডেট করা `AndroidCAStore` ভার্সন (`system:*` root CAs)
             ব্যবহার করে নতুন বিল্ড নিন, ফোনের সময় ও নেটওয়ার্ক ঠিক রাখুন, এবং
             দরকার হলে ধাপ ৭ অনুযায়ী SPKI Pin ও `diag=true` + `adb logcat -s MXL` চেক করুন।
